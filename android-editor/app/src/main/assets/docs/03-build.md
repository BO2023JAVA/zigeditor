# 编译与运行

## 图形界面 / 纯终端项目

点编辑页右上角的 ▶ 开始，流程是：

- 在 proot 的 Ubuntu 环境里执行 `zig build-lib`
- 产物是 `libmicrozig.so`，ReleaseSmall、已 strip
- 把产物替换进内置模板 APK 的 `lib/arm64-v8a/`
- 重新签名后发起安装

编译日志会在终端里逐行输出。首次编译最慢，之后走 Zig 缓存会快很多。

## 原生 zig 项目

原生项目不走模板 APK，默认执行 `zig build run`，编译产物是自己项目里的可执行文件。
侧滑栏里的「编译 so」会生成独立动态库并导出到系统下载目录。

## 常见问题

- 缺少 SDL 库：首次编译会从内置模板 APK 自动提取，模板 APK 缺失时重新进入终端会补回。
- 绑定目录缺失：日志出现 `can't sanitize binding` 说明宿主目录不存在，清理应用数据后重进终端可恢复。
- ABI 不匹配：模拟器或翻译层上 proot 无法运行，编译请在 arm64 真机进行。
- 编译成功但安装失败：多见于同包名已安装且签名不同，先卸载再装。
- 改完字体不生效：字体是编译期内嵌的，必须重新编译，不会热更新。

## 缓存

- 项目缓存：项目目录下的 `.zig-cache`
- 全局缓存：容器内的 `/tmp/zgc`
- 清理项目缓存后第一次编译会变慢，属正常现象
